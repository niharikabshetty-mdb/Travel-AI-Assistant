# 2.1 Next.js Frontend Architecture

## 1. Overview

The Travel AI Assistant uses Next.js as the frontend framework.

Next.js provides the user interface through which users can:

- Access the Travel AI Assistant
- Create an account
- Log in securely
- Enter travel requirements
- Generate AI-powered itineraries
- View structured travel plans
- Log out of the application

The frontend communicates with the backend through the Node.js gateway.

### Frontend Technology Stack

The frontend uses:

- Next.js
- React
- TypeScript
- Tailwind CSS
- Firebase Authentication

---

## 2. Why Next.js is Used

Next.js was selected because it provides a modern React-based framework for building web applications.

It provides:

- File-based routing
- React component architecture
- Server and client components
- Good application performance
- Easy integration with APIs
- Built-in development tooling

For the Travel AI Assistant, Next.js is responsible mainly for the presentation layer and user interaction.

4. App Router

The application uses the Next.js App Router.

In the App Router, folders inside the app directory are used to create routes.

For example:

app/
├── login/
│   └── page.tsx
└── home/
    └── page.tsx

creates:

/login
/home

The page.tsx file represents the page for that route.

This makes the application structure easy to understand and maintain.

5. React Components

The application is built using React components.

Components allow the user interface to be divided into smaller reusable parts.

Examples include:

-Authentication components
-Travel input components
-Itinerary display components
-Buttons
-Form fields
-Loading and error states

For example, the travel input functionality is separated into:

app/components/AssistantInput.tsx

This component handles user input related to travel planning.

6. TypeScript

TypeScript is used throughout the frontend.

TypeScript helps define the expected structure of data.

For example, the itinerary returned by the backend is represented using types similar to:

type DayPlan = {
  day: number;
  title: string;
  morning: string;
  afternoon: string;
  evening: string;
  food: string[];
  tips: string[];
};

The complete itinerary contains:

type Itinerary = {
  destination: string;
  summary: string;
  days: DayPlan[];
  travel_tips: string[];
};

Using TypeScript makes it easier to detect incorrect data structures during development.

7. Client Components

Some frontend components need to interact directly with the browser.

For example, the login page uses:

"use client";

This is required because the page uses browser-side functionality such as:

-React state
-Form interaction
-Firebase Authentication
-Navigation using useRouter

Similarly, the protected home page uses client-side authentication state to determine whether the user is logged in.

8. Firebase Authentication Integration

The Next.js frontend integrates with Firebase Authentication.

The Firebase configuration is stored separately in:

frontend/lib/firebase.ts

The application initializes Firebase and exports the authentication instance.

The frontend uses Firebase to:

-Create user accounts
-Sign users in
-Maintain authentication state
-Obtain Firebase ID tokens
-Sign users out

The frontend does not directly trust user authentication information when communicating with the backend.

Instead, it obtains the Firebase ID token and sends it to the Node.js gateway.

9. Protected Home Page

The /home page checks the Firebase authentication state.

The application uses:

onAuthStateChanged()

to determine whether a user is authenticated.

If the user is authenticated:

Login
   ↓
Firebase verifies session
   ↓
/home

If the user is not authenticated:

/home
   ↓
Authentication check
   ↓
Not authenticated
   ↓
/login

This prevents unauthenticated users from using the travel planning interface.

10. Travel Planning Flow

The frontend collects the user's travel requirements.

Example:

Destination: Jaipur
Days: 5
Travelers: 2
Interests: Food, Culture, History

The frontend then obtains the user's Firebase ID token.

The request is sent to the Node.js gateway:

Next.js
   ↓
Firebase ID Token
   ↓
Node.js Gateway

The Node.js gateway authenticates the request and forwards the travel request to the FastAPI backend.

The overall architecture is:

User
  ↓
Next.js Frontend
  ↓
Firebase Authentication
  ↓
Node.js Gateway
  ↓
FastAPI Backend
  ↓
OpenAI
  ↓
Structured Itinerary
  ↓
Next.js UI

11. API Communication

The frontend communicates with the Node.js gateway using HTTP requests.

The travel planning request is sent to:

POST http://localhost:5000/api/plan

The request contains:

{
  "destination": "Jaipur",
  "days": 5,
  "travelers": 2,
  "interests": [
    "food",
    "culture",
    "history"
  ]
}

The Firebase ID token is included in the request header:

Authorization: Bearer <Firebase ID Token>

The Node.js gateway verifies this token before allowing the request to continue.

12. Structured Itinerary UI

The frontend does not simply display the AI response as raw text.

Instead, the response is converted into structured UI elements.

Each day contains:

-Day number
-Day title
-Morning activities
-Afternoon activities
-Evening activities
-Food recommendations
-Useful tips

For example:

Day 1
├── Morning
├── Afternoon
├── Evening
├── Food
└── Tips

This provides a more readable and user-friendly travel planning experience.

13. Loading and Error Handling

The frontend provides feedback while an itinerary is being generated.

During the API request, a loading state is displayed.

If the request fails, an error message is shown to the user.

Examples include:

Your login session has expired.

or:

Unable to generate your travel plan.

This prevents the application from appearing unresponsive when the backend is processing the request.

14. Logout

Authenticated users can log out from the home page.

Firebase's sign-out functionality is used to terminate the user's authentication session.

After logout, the user is redirected to:

/login

This ensures that the protected travel assistant page is not accessible after logout.

15. Responsive User Interface

The frontend uses Tailwind CSS and custom CSS to create a responsive interface.

The UI is designed to work across different screen sizes.

The main design goals are:

-Clean layout
-Simple navigation
-Easy-to-use travel form
-Attractive itinerary cards
-Clear authentication interface
-Responsive spacing and typography

16. Worldwide Destination Support

The frontend accepts a free-text destination.

The application does not restrict the user to a fixed list of destinations.

For example, users can enter:

Jaipur

or:

Tokyo

or:

Paris

or:

New York

or any other destination.

The destination is passed to the AI backend, which generates an itinerary based on the requested location.

The current application does not claim live information such as:

-Current flight prices
-Current hotel availability
-Exact ticket prices
-Exact opening hours

Such information would require integration with live external APIs or data sources.

17. Benefits of the Architecture

The Next.js frontend architecture provides several benefits.

Separation of Concerns

The frontend focuses on:

-User interface
-User interaction
-Authentication state
-API communication
-Itinerary presentation

The backend handles AI processing and data operations.

Maintainability

The application is divided into pages and components, making future modifications easier.

Type Safety

TypeScript provides better control over the structure of API responses and application data.

User Experience

The structured itinerary interface is easier to read than raw AI-generated text.

Security

Authentication is handled using Firebase, while the Node.js gateway verifies the authentication token before forwarding requests.

18. Conclusion

Next.js forms the frontend layer of the Travel AI Assistant.

It provides the application's:

-Landing page
-Authentication interface
-Protected travel dashboard
-Travel input form
-Loading and error states
-Structured itinerary presentation
