# 2.3 FastAPI Framework

## 1. Overview

FastAPI is used as the AI backend of the Travel AI Assistant.

The FastAPI service is responsible for:

- Receiving travel planning requests
- Validating incoming data
- Preparing the AI prompt
- Communicating with the OpenAI API
- Generating a structured travel itinerary
- Returning the itinerary to the Node.js gateway

The FastAPI backend runs separately from the Node.js gateway.

The architecture is:

```text
Next.js Frontend
       ↓
Node.js Gateway
       ↓
FastAPI Backend
       ↓
OpenAI
       ↓
Structured Travel Itinerary

2. Why FastAPI is Used

FastAPI is a modern Python web framework designed for building APIs.

It was selected for the Travel AI Assistant because the AI processing layer is implemented in Python.

FastAPI provides:

Simple API development
Automatic request validation
Python type hints
Automatic API documentation
Easy integration with Python libraries
Good performance for API-based applications

In this project, FastAPI acts as the AI service layer.

5. FastAPI Application

The application is created using:

from fastapi import FastAPI

app = FastAPI(
    title="Travel AI Assistant API",
    description="AI-powered backend for the Travel AI Assistant",
    version="1.0.0",
)

This creates the main FastAPI application.

The application also provides metadata such as:

API title
API description
Version

This information is used by FastAPI's automatic documentation system.

6. Running the FastAPI Server

During development, the FastAPI server can be started using Uvicorn.

From the fastapi-backend directory:

uvicorn main:app --reload --port 8000

The backend is then available at:

http://127.0.0.1:8000

The --reload option automatically restarts the server when Python source code changes.

This is useful during development.

http://127.0.0.1:8000/health

{

This endpoint allows the developer to quickly check whether the FastAPI service is running.

8. Pydantic Request Validation

FastAPI uses Pydantic models to validate incoming request data.

The Travel AI Assistant defines the following request model:

class TravelRequest(BaseModel):
    destination: str = Field(..., min_length=2)
    days: int = Field(..., ge=1, le=30)
    travelers: int = Field(..., ge=1, le=20)
    interests: list[str] = Field(default_factory=list)

This defines the expected structure of a travel request.

9. Travel Request Fields

The request contains four main fields.

Destination
destination: str

The destination must be a string containing at least two characters.

Example:

"destination": "Paris"
Number of Days
days: int

The number of days must be between 1 and 30.

For example:

"days": 5
Number of Travelers
travelers: int

The number of travelers must be between 1 and 20.

For example:

"travelers": 2
Interests
interests: list[str]

This contains the user's travel interests.

Example:

"interests": [
  "food",
  "culture",
  "history"
]

If no interests are provided, an empty list is used.

10. Example API Request

The FastAPI travel planning endpoint accepts data similar to:

{
  "destination": "Tokyo",
  "days": 5,
  "travelers": 2,
  "interests": [
    "food",
    "culture",
    "technology"
  ]
}

FastAPI automatically validates this request against the TravelRequest model.

11. Automatic Validation

One major advantage of using FastAPI with Pydantic is automatic validation.

For example, the following request is invalid:

{
  "destination": "",
  "days": 0,
  "travelers": 0
}

The request violates the validation rules.

FastAPI automatically returns a validation error instead of allowing invalid data to reach the AI processing logic.

This reduces the amount of manual validation code required.

13. Preparing User Interests

The user's interests are converted into a readable string before being added to the AI prompt.

The implementation is:

interests_text = ", ".join(request.interests)

If the user does not provide interests, a default description is used:

general sightseeing, local food, culture,
and memorable experiences

This ensures that the AI still has useful preferences to consider.

14. AI Prompt Construction

The FastAPI backend creates a prompt for the AI model.

The prompt contains the user's travel requirements:

Destination
Number of days
Number of travelers
Interests

For example:

Destination: Tokyo
Number of days: 5
Number of travelers: 2
Interests: food, culture, technology

The backend instructs the model to create a practical itinerary for the requested number of days.

17. JSON Schema

The backend defines a JSON schema for the AI response.

The schema specifies:

Required fields
Data types
Structure of each itinerary day
Arrays for food recommendations
Arrays for useful tips

The model is instructed to return only the requested structured format.

This makes the AI response predictable and easier for the frontend to display.

18. OpenAI Integration

The FastAPI backend uses the OpenAI Python SDK.

The SDK is initialized using an API key stored in an environment variable.

The application loads environment variables using:

from dotenv import load_dotenv

load_dotenv()

The API key is retrieved using:

OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")

The OpenAI client is then created using the configured API key.

The actual API key is never stored directly in the source code.

19. Environment Variables

The backend uses a .env file for sensitive configuration.

The structure is similar to:

OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=your_configured_model

The actual secret value must never be included in documentation or committed to GitHub.

The .env file is excluded through Git configuration.

This reduces the risk of accidentally exposing API credentials.

20. OpenAI Request

The FastAPI backend sends the travel planning prompt to the configured OpenAI model.

The application uses the Responses API through the OpenAI Python SDK.

The response is requested in a structured JSON format.

Conceptually:

response = client.responses.create(
    model=OPENAI_MODEL,
    input=prompt,
    text={
        "format": {
            "type": "json_schema",
            "name": "travel_itinerary",
            "strict": True,
            "schema": schema,
        }
    },
)

The generated output is then obtained using:

itinerary_text = response.output_text
21. Converting the AI Response

The AI response is returned as structured JSON text.

Python's JSON module is used to convert the response into a Python object:

itinerary = json.loads(itinerary_text)

The resulting object can then be returned by FastAPI.

22. FastAPI Response

After successful AI generation, the endpoint returns:

return {
    "success": True,
    "destination": request.destination,
    "days": request.days,
    "travelers": request.travelers,
    "itinerary": itinerary,
}

This response is then sent back to the Node.js gateway.

The flow is:

FastAPI
   ↓
OpenAI
   ↓
Structured JSON
   ↓
FastAPI Response
   ↓
Node.js Gateway
   ↓
Next.js Frontend
23. Error Handling

The backend handles possible errors during AI generation and JSON processing.

If the AI response cannot be parsed as valid JSON, the backend raises an HTTP error:

raise HTTPException(
    status_code=500,
    detail="AI returned an invalid itinerary format.",
)

Other unexpected errors are also handled:

raise HTTPException(
    status_code=500,
    detail="Unable to generate the travel itinerary.",
)

This prevents raw internal errors from being directly exposed to the frontend.

24. Automatic API Documentation

FastAPI automatically generates API documentation.

When the server is running, the interactive Swagger documentation is available at:

http://127.0.0.1:8000/docs

FastAPI also provides an alternative documentation interface at:

http://127.0.0.1:8000/redoc

The documentation is generated from the application's routes and request models.

This makes it easy to inspect and test the backend API during development.

29. Current Limitations

The current FastAPI service generates travel plans using the information supplied by the user and the AI model.

It does not currently connect to live external travel-information APIs.

Therefore, the application does not guarantee real-time:

Flight prices
Hotel availability
Exact ticket prices
Exact opening hours
Live weather information
Real-time transportation schedules

If such functionality is required in the future, external APIs or live data sources can be integrated.
